# ZapFormat

Интернет-магазин автозапчастей. Проект разделён на публичный сайт (GitHub Pages) и защищённый сервер с базой данных.

## Адреса

- Витрина: https://korrestconsult.github.io/ZapFormat/
- Backend API: https://api.168.113.211.246.sslip.io
- Репозиторий: KorRestConsult/ZapFormat (ветка `main`)

## Покупательский интерфейс

- Главная: поиск по артикулу или названию, состояние подключения поставщика.
- Каталог: точные позиции и аналоги, сортировка, фильтры, подбор по названию.
- Корзина: просмотр без входа, сохранённые позиции, проверка цены/остатков перед заказом.
- Личный кабинет: обзор, заказы, гараж, профиль, получение, уведомления, возвраты, статистика.
- Навигация: адаптивная для компьютера, планшета и телефона.

**Важное ограничение:** публичный поиск и просмотр корзины доступны гостю, но создание заказа требует авторизации. При отсутствии подтверждённого подключения поставщика оформление отключено; сохранённые цены не считаются актуальными.

## Сервер

- Node.js и PostgreSQL, код в `backend/`.
- Сессии и личные данные хранятся на сервере. Ключи API поставщиков нельзя публиковать в GitHub.
- Состояние API: `GET /api/health`.
- Реальное подключение поставщика: `GET /api/supplier/health` (отдельно от общей работоспособности сервера).
- Возможности регистрации: `GET /api/auth/capabilities`.

### Ограничения на момент подготовки

Подключение PartGrade зависит от разрешения нового IP и конфигурации API на сервере. SMS-регистрация и восстановление пароля требуют настроенного SMS-провайдера. VIN-каталог через отдельную интеграцию требует собственных разрешений и ключей; у PartGrade VIN-подбора нет.

Не показывать клиентам фиктивное наличие и не запускать реальные закупки поставщику в процессе тестов.

## Публикация и проверки

**Сайт:** GitHub Pages публикует файлы фронтенда из `main`.

**Backend:** workflow `.github/workflows/deploy.yml` реагирует на изменения `backend/**` или самого workflow; поддерживает также ручной запуск. Деплой требует настроенного исполнителя на сервере и необходимых секретов. Успешная публикация сайта не означает успешного серверного деплоя.

**Frontend QA:** `.github/workflows/frontend-checks.yml` проверяет изменения сайта независимо от сервера. `tests/ui-contract.test.mjs` проверяет маршруты, HTML-ID, разделы кабинета, адаптивную вёрстку, авторизацию и защитные условия оформления.

Локальная проверка без внешних зависимостей:

```bash
node --check app.js
node --check config.js
node --test tests/ui-contract.test.mjs
```

## Контроль перед началом продаж

Проверить подтверждённый доступ к PartGrade с IP сервера, реальную выдачу цен и остатков, регистрацию/восстановление, корректность корзины и доставки, перепроверку предложений перед оформлением и весь цикл заказа на тестовых данных. До завершения этих проверок магазин нельзя считать готовым к реальным продажам.
